Line 3 is listed last on purpose, and it is deliberately NOT "the maker's dust balance is
unchanged" — the assertion a reader expects. That assertion is unavailable and would be
misleading if it were: the pinned facade's dust accessors return 0 even for a wallet that is
demonstrably paying fees (00005's own wallet report printed `DUST=0` for the genesis wallet
while it was funding the entire run), and dust is GENERATED over time so a maker's real
balance can legitimately RISE across a settlement it did not pay for. It would also be
trivially satisfiable by using an unfunded maker, which would prove nothing at all. So what
is asserted instead is that the maker COULD have paid — it holds NIGHT registered for dust
generation — and that the decisive reading is line 2.

Settlement fee / plain-transfer fee ≈ **3.03×**.

The offer's OWN `fees()` figure is `1933650000000001` SPECKs. That is **not** the settlement
fee and must not be quoted as one: the fee actually paid belongs to the MERGED transaction the
taker submits, whose size the maker cannot know in advance.

And the direction of the error matters: the offer's own figure is **2.00× the fee actually paid**. It OVERSTATES the real cost, so a maker that quoted it to a taker would be asking them to budget for more than the settlement needs — annoying but safe. 
Either way the figure a taker should reason about is the merged transaction's, which only
exists after balancing — so an offer format cannot promise a settlement fee, and this one
does not try to.
